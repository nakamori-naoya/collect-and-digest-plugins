# セッションの日次記録に共通する条件

この条件は、実行の担当が make-session-digest で作った agent-session-digest 型の日次記録（以下、資料）と、最後の報告（以下、報告）を判定するためのものである。資料は共有されるものとして書かれ、原文にあったことは書いてよい理由にならない。条件は判断の型だけを書き、正しい資料の中身は書かない。重み3は利用者の原則の芯（共有されるものとして書く、原文を複製しない、推測で埋めない）、重み2は資料の骨組み、重み1は細部である。資料が存在しないか空のときは、資料を読む条件はすべて FAIL とする。

## 共有されるものとして書く

### no-identifying-names

重み: 3

材料のセッションの原文を読み、顧客名、組織名、人の氏名、repository の名前を拾ってから、資料の本文と front matter（タグを含む）を探す。

PASS：原文にある顧客名、組織名、人の氏名、repository の名前、案件名が、資料のどこにも無い。人や顧客は役割で、固有名は変更の種類で書かれている。伏せ字、先頭の数文字、ハッシュ化で残したものも無い。

FAIL：原文の固有名が、そのままか、伏せ字や一部を残した形で、資料のどこかにある。

### no-secrets-or-paths

重み: 3

PASS：原文にある秘密値（パスワード、トークン、鍵）と、絶対パス、作業ディレクトリ、native のセッション ID が、資料のどこにも無い。秘密値に関わる作業は、作業の意味（「認証設定を扱った」など）で書かれているか、省かれている。

FAIL：秘密値、絶対パス、作業ディレクトリ、native のセッション ID のどれかが、資料のどこかにある。

### no-verbatim-copy

重み: 3

PASS：資料は、原文の会話をなぞったり長く引用したりせず、達成、変更、判断、検証、未解決に組み直して書かれている。原文の全文や途中の要約を、資料のほかのファイルとして作業場所の成果物に残していない。

FAIL：原文の発言が長く引用されている、会話の時系列をなぞっている、または原文の写しや途中の要約がファイルとして成果物に残っている。

## 推測で埋めない

### no-invented-content

重み: 3

PASS：資料に書かれた達成、判断、検証、未解決は、どれも材料のセッションの原文にある。原文に無い検証を実行したことにしていない。タグは、利用者が明示した別名が無いので空である。

FAIL：原文に無い作業、判断、検証の結果が書かれている、またはタグに原文から推測した名前が入っている。

## 形と報告

### front-matter-from-material

重み: 2

PASS：front matter の対象日、セッションの件数、入力の hash、セッションごとの不透明化した source_id が置かれ、不透明化の前の ID や推測で埋めた値が無い。

FAIL：これらの値が欠けているか、推測の値や不透明化の前の ID が入っている。

### report-contents

重み: 1

PASS：報告に、保存した日次記録のパス、セッションの件数、入力の hash が書かれ、報告にも原文の秘密値や固有名が無い。

FAIL：報告にこれらのどれかが無い、または報告に原文の秘密値か固有名がある。
